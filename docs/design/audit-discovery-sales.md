# Discovery, curation, and sales: page redesign audit

Source review: 5 October 2026. This is a proposed design, not a claim that the production screens have been visually tested. References point to the current React/CSS implementation. No production components were edited. The Emil design-engineering skill and review-animations skill/STANDARDS were read and applied; their required Before/After/Why format appears below.

## Design direction and scope

Give discovery the character of a quiet gallery and sales the clarity of an advisor's working desk. Warm off-white page canvas, white artwork mounts, ink typography, muted olive primary action, and restrained status colors allow artwork to supply most of the color. Use serif display headings for page names and artwork titles, with sans-serif body text, controls, figures, and data tables. Dense tools retain compact type and consistent 44px minimum touch targets. Avoid turning operational pages into oversized editorial covers.

Use the shared application shell, but give each task its own composition: an image-led catalog, focused tasting stage, curated suggestions, compact customer queue, split customer workspace, proposal composer, and collector review room. Keep customer-facing and seller-facing controls distinct. New client-side view/filter controls proposed below should derive from already loaded data; do not imply unsupported search, persistence, commercial automation, checkout, or payment services.

## 1. Artwork Catalog

**Goal:** Find and inspect available works; customers express taste, while sellers manage inventory, price visibility, privacy, and Taster eligibility.

**Role variants:** Customers get like/dislike and price-visibility enforcement. Non-customers get selection, edit/delete, and bulk tools. Dealer/domain owner/global admin see customer feedback. Only global admin gets a domain selector. Bulk privacy changes are allowed only when every selected artwork was uploaded by the current user (`frontend/src/pages/Catalog/CatalogPage.tsx:164`, `:341`, `:905`). Do not broaden those permissions for visual consistency.

**Proposed full page:** compact title and count; one search bar; a secondary toolbar with sort, ended-auction visibility, and optional liked/disliked filter chips; an open gallery of consistently mounted, uncropped images. Artist, title, medium/year, and price sit below the image in a fixed hierarchy. Status chips sit outside the artwork area. Seller mode has a visible selection control and an optional compact inventory table using the same records. Selection replaces the secondary toolbar with count and grouped actions; it does not add a second permanent toolbar. Artwork detail uses a wide inspection dialog with large image left, descriptive facts/actions right, and seller feedback below in tabs.

## 2. Taster

**Goal:** Capture honest like/dislike choices quickly enough to build a taste profile. This is a focused decision task, not shopping.

**Proposed full page:** a restrained “Taster” header with a small progress line (“12 of 20 tastes to unlock suggestions,” when applicable), a single oversized artwork mount, artist/title underneath, and two explicit text + icon actions: “Not for me” and “I like this.” Keep desktop arrow-key hints small. Once eligible, replace threshold copy with total tastes rather than implying a finite remaining session. Do not add undo or skip until their data semantics are implemented.

## 3. AI Suggestions

**Goal:** Help a collector evaluate personalized works and provide feedback; help sellers understand recommendations and curate a proposal.

**Role variants:** dealer, domain owner, and global admin can see Match and score breakdown. Customers cannot. Seller embedded mode displays customer feedback read-only, allows proposal inclusion, and can include rated works. Customers can like/dislike and edit comments, which currently save on blur (`AISuggestionsPage.tsx:63`, `:105`, `:681`).

**Proposed full page:** customer view uses a quiet intro, then image-led rows or large cards with title, artist, permitted price, current preference, and a compact “Add feedback” action that expands a labeled field. Seller view adds a clearly identified customer context, Include rated switch, a right-side selected-works tray, and expandable “Why suggested” evidence on each work. The visual algorithm score must not outrank the image. The tray and feedback expansion are frontend presentations of existing state, not new shortlist storage.

**Score semantics:** `Image` = visual similarity to taste vectors; `Intent` = questionnaire buying-interest match; `Metadata` = artists/mediums/tags overlapping prior likes/dislikes; `Behavior` = small recency and auction-status adjustments. Keep unknown component values distinct from genuine zero if changing formatting. Current match is `probabilityMatch` formatted as a percentage; the name does not establish a purchase probability. Do not relabel it “chance of buying,” “confidence,” or imply the displayed components sum to the headline (`AISuggestionsPage.tsx:60`, `:63`, `:351`).

**Controls/states to preserve:** detail open/close; customer like/dislike; note editing/autosave; seller read-only note and preferences; seller include-rated control where enabled; seller add/remove proposal; eligibility CTA; initial/loading more/infinite-scroll; no suggestions; request error; ended-auction disabled addition; price visibility; missing image; explanatory tooltip; full medium/dimensions/description in detail. Add an explicit Load more fallback without removing existing pagination behavior.

**Mobile:** one spacious artwork card; feedback expands inline; proposal selection becomes a bottom tray button. No side-by-side score grid small enough to require squinting. Seller evidence occupies a collapsible full-width region and never leaks into customer mode.

**Motion:** no animated reordering as votes change; retain position while saving. Pointer-open detail/evidence popover 180–220ms with trigger-aware origin for anchored content. Keyboard opening is instant; reduced motion fades only. Selected state changes immediately; no bouncing “Added” badges.

## Motion audit verdict

| Before                                                                                                                                                              | After                                                                                                        | Why                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| Keyboard ratings wait on a 300ms fly-out (`TasterPage.tsx:245`, `:395`).                                                                                            | No keyboard animation or fixed delay.                                                                        | High-frequency and keyboard actions violate the supplied skill's central rule. |
| Taster repeated swipe keyframes (`TasterPage.css:132`) and ungated 1.1 hover scale (`:325`).                                                                        | Delete routine fly-outs; interruptible gesture transforms only; fine-pointer hover gate and no hover growth. | Frequency, interruptibility and touch correctness.                             |
| Taster `transition: all` (`TasterPage.css:316`); catalog input/filter `all` (`CatalogPage.css:47`, `:463`); AI card `transition-all` (`AISuggestionsPage.tsx:533`). | Explicit relevant properties only; no card shadow animation.                                                 | Prevents accidental property animation and paint work.                         |
| Catalog 500ms image zoom (`CatalogPage.tsx:1255`).                                                                                                                  | Remove zoom.                                                                                                 | Repeated decoration exceeds the intended sub-300ms UI budget.                  |
| No reduced-motion clause in the reviewed Taster CSS.                                                                                                                | Reduced motion removes rotation/translation while keeping concise opacity/state feedback.                    | Necessary motion accommodation for the redesigned gesture surface.             |
| Sales tab panel has `animate-in fade-in duration-300` (`SalesPage.tsx:2378`).                                                                                       | Instant tab panels, especially for keyboard navigation.                                                      | Repeated workflow navigation should feel direct.                               |

**Feel-breaking regressions:** block existing keyboard-triggered swipe delay from carrying into the redesign. **Missed simplifications:** remove card zoom, routine fly-outs, tab panel entrance. **Interruptibility & timing:** distinguish pointer gestures from button/keyboard choices. **Accessibility:** add reduced-motion behavior, fine-pointer hover gates and reliable focus management.

**Decision: Block carrying the current motion unchanged.** Proposed common motion tokens: `cubic-bezier(0.23,1,0.32,1)` for entry/exit, `cubic-bezier(0.32,0.72,0,1)` for drawers; press 100–160ms, tooltip 125–180ms, occasional dialog 220ms entry/160ms exit; transform/opacity only.
