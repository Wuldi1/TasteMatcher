# TasteMatcher Web API

NestJS API for authentication, domains, users, artwork/catalog workflows,
uploads, sales/proposals, and health checks.

## Prerequisites

- Node.js 24 LTS
- pnpm 10 (enabled through Corepack)
- Azure CLI and `jq` for the local-production configuration sync
- Azure access to subscription `e105e38a-7820-4c7e-b1da-de05227d6355`

From the repository root:

```sh
corepack enable
pnpm install --frozen-lockfile
```

## Local API with production data

This mode runs the API on your machine while using the existing production
Azure dependencies. It can read and modify real production data. Do not use
write endpoints unless the production change is intentional and reviewed.

Run the sync command. It reuses a valid Azure CLI session, opens `az login`
only when authentication is required, and selects the confirmed production
subscription automatically:

```sh
./scripts/azure/sync-local-production-config.sh
```

The sync is read-only with respect to Azure. It verifies the exact subscription,
resource group, Web App, and Function App, then creates ignored
`webapi/.env.local-production` and `functions/local.settings.json` files with
permissions `600`. Every Function trigger is disabled in the generated file. It
never prints setting values. Do not share or commit either generated file.

Start the local API from the repository root:

```sh
pnpm --filter @tastematcher/webapi start:local:production
```

The guarded profile uses `NODE_ENV=development` for local runtime behavior and
separately declares `TASTEMATCHER_DATA_ENV=prd`. Startup fails unless the
production-data acknowledgement and verification-only email mode are present. In this
mode:

- only login/domain verification email can be delivered;
- invitations, proposal notifications, and bulk/custom email are disabled;
- random authentication codes remain enabled;
- `POST /auth/test/create-domain` is disabled;
- Azure Functions are not started automatically.

The API listens at `http://localhost:8080`. Begin with the read-only health
check:

```sh
curl --fail http://localhost:8080/health
```

After signing in, use an existing authenticated `GET` endpoint for a read-only
data smoke test. Avoid `POST`, `PUT`, `PATCH`, and `DELETE` requests unless you
explicitly intend to change production. Starting Functions locally is a
separate, side-effecting operation because queue consumers can mutate data; it
is intentionally outside this API workflow.

Never put secrets in `.env.example`. The only supported local data profile is
the guarded production-backed profile generated by the sync command above.

## Quality checks

```sh
pnpm --filter @tastematcher/webapi test
pnpm --filter @tastematcher/webapi lint
pnpm --filter @tastematcher/webapi typecheck
pnpm --filter @tastematcher/webapi build
```

Compiled output is written to `webapi/build`. Environment files are neither
required in nor copied into that directory or deployment archives.
